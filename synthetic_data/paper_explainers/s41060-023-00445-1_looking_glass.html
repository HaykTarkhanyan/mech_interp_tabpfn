1. The paper in one minute

The question. How faithfully do model-agnostic explanation methods describe what a model actually computes ("internal fidelity"), on tabular data, where such checks are rare? Use models whose reasoning can be read directly, glass boxes, and compare.

The answers.

  1. Setup. 14 public datasets (7 classification, 7 regression), 35 glass-box models: a CART decision tree everywhere, logistic regression and Gaussian naive Bayes for classification, linear regression for regression. Four explainers: LIME, SHAP, LINDA-BN and ACV (Sections 4.1-4.3).
  2. Reference. For a tree, the "true features" are those on the instance's decision path; for linear and logistic models, those whose coefficient is within the top 5% of the coefficient range; for naive Bayes, the analogous likelihood difference. Rankings by path position or coefficient size (Table 5).
  3. Results. LIME and SHAP are "generally precise" but incomplete; no method ranks features well; LIME is poor on naive Bayes and good on linear models; SHAP is poor on linear and logistic models but very precise on trees; all differences are significant (Tables 7-10).
  4. Conclusion. No method is best everywhere; the explanation mechanism and the setup decide quality, so experts are needed to choose (Section 7).
My take, one line. Using glass boxes as the reference is the right idea, and the paper is honest that it is not looking for a winner. But its two headline verdicts come from how the reference is defined: "SHAP fails on linear models" because the reference is coefficient size while SHAP reports contributions, and "precise but incomplete" because on trees the reference set is the whole decision path while the explanation set is usually one feature.

2. Background you need first

Internal versus external fidelity (Section 2.3). External fidelity asks whether an explanation's implied prediction matches the model's prediction. Internal fidelity asks whether the explanation matches how the model computed it, for example the weights it uses or the path it follows in a tree. Only a model you can read lets you check the second.

The four explainers. LIME fits a ridge regression to the model's outputs on perturbed copies of the instance and returns its coefficients. SHAP returns Shapley values; here TreeSHAP for trees, LinearSHAP for linear and logistic models, and the exact or permutation explainer for naive Bayes. LINDA-BN learns a small Bayesian network around the instance; the paper turns it into importances as |P(f(x)) - P(f(x) | xi)| (Eq. 15). ACV trains a random-forest surrogate and returns minimal sets of features sufficient for the prediction, with a "local explanatory importance" score for ranking.

The evaluation (Sections 3.2, 4.2-4.4). "Top 5% of range" keeps every weight at or above max - 0.05·(max - min) (Eqs. 11, 14), which often keeps a single feature.

Preprocessing (Section 4.1). Categorical variables one-hot encoded (up to 117 columns for Mushroom), numeric features min-max scaled to [0, 1], classification data balanced by downsampling, a 70/30 split, and the explainers run on a sample of the test set.

3. Finding 1: "SHAP fails on linear models"

What they found. SHAP "does show poor performance when explaining logistic and linear regression models", while LIME's explanations for those models "are more faithful than that of SHAP" (Section 5). On linear regression (Table 8), LIME's precision falls below 0.5 only for the two all-continuous datasets (Real Estate 0.40, Wine Quality 0.43), and is perfect on Facebook, Solar Flare and Student Scores. SHAP reaches 0.08 on Student Scores. Across the 14 linear and logistic models, LIME is more precise in 11 (my count from Tables 7-8).

Precision of the explanation set against the top-5% coefficient set, linear regression models (Table 8).

The paper's own explanation (Section 6.3): SHAP values "are not defined as the importance of a feature to the model"; LinearSHAP computes φi = wi(xi - E[xi]) (Eq. 16), which "do[es] not fully align with model importance". Table 11 then lists, among SHAP's weaknesses, "Cannot accurately work with linear and logistic regression models", and recommends SHAP for "End user decision-making", "Not for investigations of model quality".

My take: the diagnosis is right; the verdict should have gone the other way. For a linear model, wi(xi - E[xi]) is the exact Shapley value of that model, so SHAP is correct by its own definition. LIME fits a ridge regression to a linear function and recovers wi almost exactly, which matches a reference defined as coefficient size by construction. The comparison measures which method returns the coefficient vector, the same trap OpenXAI falls into (see that explainer). Section 6.3 sees this and then keeps the verdict. With min-max-scaled features, an instance near a feature's mean gets a small SHAP value for a large coefficient; whether that is an error depends on the question, not on the method. How sure: high.

4. Finding 2: "precise but incomplete"

What they found. "LIME explanations generally have high precision coupled with low-to-moderate recall scores, indicating that a large number of relevant features are missing from the subset"; SHAP likewise shows "high precision ... but poor recall" (Section 5.1). For users: "highly weighted features are truly relevant", but "other factors could have impacted on the model prediction" (Section 6.1).

Mean precision minus recall by glass-box type, my computation from Tables 7-8 (14 decision trees, 7 logistic regressions, 7 linear regressions, 7 naive Bayes models).

My take: the gap is mostly a set-size effect. The precision-recall gap is about 0.55-0.60 for decision trees and about zero for logistic regression and naive Bayes. For a tree, the true set is every feature on the decision path, usually several. The explanation set is everything within 5% of the top weight, often one feature. A one-feature set that hits the path has precision 1 and recall 1/(path length), whatever the explainer does. Where the true set uses the same top-5% rule (logistic regression, naive Bayes), precision and recall are nearly equal, often identical (0.68/0.68, 0.82/0.82 in Table 7), which is what single-feature sets on both sides produce. So "precise but incomplete" describes the scoring rule more than the explainers. The ranking metric (Kendall tau-b) avoids this and is the more trustworthy column; SHAP's mean tau on trees is 0.66 against LIME's 0.41 (my averages). How sure: high on the pattern; medium on the exact set sizes, which the paper does not report.

5. Finding 3: the threshold, LINDA-BN, ACV and the tests

Choosing 5% (Section 4.4, Fig. 3). For every dataset, model and explainer, they tried thresholds from 0.05 to 0.5 and computed the F1 match between true and explanation sets. Out of 126 experiments, 38 were ties and were set aside; of the remaining 88, 0.05 gave "the most faithful subsets" in 49 (Fig. 3: about 49 at 0.05, about 12 at 0.5, 2 to 5 at each value in between, approx.). So 0.05 was chosen.

LINDA-BN and ACV. LINDA-BN has high recall and low precision because, when the model is confident, many features get similar scores and a large set is returned (Section 6.1). ACV is the least consistent and "generally performed poorly across all measures"; its surrogate was tuned to high external fidelity, which "does not translate into high internal fidelity" (Section 6.5).

Significance. Wilcoxon signed-rank tests find every pair of explainers different on every metric, with p printed as 0.00 throughout (Tables 9-10).

My take. Choosing the threshold that maximizes measured fidelity, then reporting fidelity at that threshold, tunes the evaluation on its own outcome; the 0.05 choice also produces the single-feature sets behind Finding 2. The counting in Section 4.4 sets the 38 ties aside and then counts "another 38" ties among the remaining 88. The Wilcoxon statistics (T up to about 540,000) imply per-instance pairs pooled across datasets and models, so the tests treat thousands of correlated instances as independent; p = 0.00 says little. The naive Bayes reference, a difference of two class-conditional Gaussian densities at xi (Eq. 13), grows when a feature's class distributions are narrow, which is a scale effect, not importance. How sure: high on the counting and the threshold choice; medium on the tests (the pairing unit is not stated) and on the naive Bayes reference.

6. Try it: the reference picks the winner

Made-up linear model, not from the paper: f(x) = 2.0·x1 - 1.5·x2 + 1.0·x3 + 0.3·x4 on min-max-scaled features with means (0.5, 0.3, 0.6, 0.5); x3 = 0.9 and x4 = 0.2 are fixed. LIME is idealized as recovering the coefficients exactly, which a ridge fit of a linear model nearly does; SHAP is LinearSHAP, w_i(x_i - E[x_i]). Bars are normalized absolute importances; scores are Kendall tau-b against the chosen reference.

7. My critique

What's good. Glass-box references are the cleanest way to check internal fidelity, and the paper uses 14 datasets with varied variable types rather than the usual two or three. It explains why each method behaves as it does (surrogate choice, permutation scheme, SHAP implementation) instead of only ranking them. It says plainly that it is not looking for a best method, that glass-box fidelity may not transfer to black boxes, and that LINDA-BN and ACV were not designed for attribution.

8. How it connects to your work

Everything in this section is my own analysis.

Same idea as your "reality", one step shorter. A known function as the reference is your nested design's reality (DECISIONS #22). Looking Glass explains the glass box itself; your pilot trains a model on data from the known function and scores against that trained model's exact interventional SHAP values (err_model), with the known function's values alongside (err_data). That extra step is what makes the result about learned models, which is the limitation the authors name in Section 6.7.

The cautionary example for your estimand section. Your reference is interventional SHAP, so occlusion, LIME, Saabas and path-dependent TreeSHAP in your explainer list are scored as estimators of it. Looking Glass shows what happens when that is not stated: a correct method gets labeled as broken. Cite it when you justify the estimand, and state the scope of your rankings.

Keep continuous metrics. Your primary metric is pairwise agreement on reality's resolved pairs, and explainer error is a continuous relative error. If you add any top-k set metric, use equal set sizes on both sides, or Finding 2 happens to you.

Fix evaluation choices before seeing results. DECISIONS #24 fixed the primary metric before the full run; Looking Glass's threshold choice is the counterexample to point at.

9. Glossary
Glass-box modelA model whose reasoning can be read directly: a decision tree, a linear or logistic regression, naive Bayes.
Internal fidelityDoes the explanation match how the model computed the prediction?
External fidelityDoes the explanation's implied prediction match the model's prediction?
Precision, recallShare of explanation features that are true features; share of true features the explanation found.
Kendall tau-bRank correlation that handles ties; 1 means identical orderings.
LinearSHAPExact Shapley values for a linear model, w_i(x_i - E[x_i]), assuming independent features.
LINDA-BNA local Bayesian network fitted around one instance.
ACVActive Coalition of Variables: minimal sufficient feature sets from a random-forest surrogate.
ICE plotIndividual conditional expectation: the prediction as one feature varies, one curve per instance.
Wilcoxon signed-rank testA paired, rank-based test of whether two methods' scores differ.

10. How to read the actual paper
  1. Pages 1-6: motivation, the three research questions (Section 2.4) and the metrics (Section 3.2).
  2. Pages 7-12: how the true and explanation sets are extracted (Tables 5-6, Eqs. 11-15, Section 4.4 and Fig. 3). This is where the results are decided.
  3. Pages 13-14: Tables 7-8. Read them with the decision-tree rows and the linear rows side by side.
  4. Pages 15-19: the discussion, especially Section 6.3 (SHAP) and Table 11.
  5. Skip on a first read: the LINDA-BN and ACV background (Sections 2.2.3-2.2.4) and Tables 9-10.

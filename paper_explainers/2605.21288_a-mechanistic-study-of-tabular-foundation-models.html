1. The paper in one minute

The question. Three tabular foundation models (TabPFN v2, TabICL v2 and Mitra) get almost the same accuracy on the authors' 49 classification datasets: 0.854, 0.864 and 0.860. They are built differently. Do they compute the same thing inside, or reach the same answers by different routes?

The answers.

  1. Different routes. TabPFN v2 and Mitra predict with a vote: at layer 9 the test row (the "query") looks hard at a few training rows, and their labels, weighted by how hard it looks, give the prediction. TabICL v2 instead builds one average point per class (a "prototype") and picks the class whose prototype is nearest. Swap these rules between models and accuracy collapses by 33-40 points.
  2. Most layers are not essential. Each model has one early block that "sets up the coordinate system". Remove it and things break. Many other blocks can be removed for a few points of accuracy.
  3. Order sensitivity is accidental and fixable. Shuffling the columns can change accuracy by up to 8 points. That comes from a few position-related parameters that the trained models barely use. Zeroing them makes the models exactly order-blind, and accuracy doesn't change.
  4. "Representation collapse" is real in theory but not in practice. Models that ignore column order can't tell some rows apart. They prove this with tiny hand-built models. The released models each have two backup defenses, so you only see the failure after removing both.
  5. Mechanism-based attacks. Knowing the mechanism, they design data changes meant to hurt each model specifically: flip the labels of the most "central" rows, or replace values by their ranks.
My take, one line. Much more rigorous than McCarter's blog post, and finding 1 for TabPFN (the layer 9 vote) is solid and worth citing. But the abstract oversells its causal evidence, one headline plot (the "late" probe) looks like a measurement artifact, and the attack section doesn't support its own claims. Details in section 8.

2. Background you need first

2.1 In-context learning on a table

You don't train TabPFN on your data. You hand it the whole training table (the "context rows", with their labels) together with the test row (the "query", label unknown), and one forward pass outputs class probabilities for the query. Everything the model "learned" happened in pretraining on millions of synthetic tables. So "how does it predict?" means "what algorithm did pretraining put into the weights?".

2.2 What "readout" means

The readout is the last step: how the network turns its internal numbers into a prediction. The paper's main move is to look for a simple rule (a vote, a nearest-average, a nearest-neighbor) that, applied to the network's internal state, reproduces the network's own predictions. If a simple rule matches the model, you have a compact description of what the model computes.

2.3 The three models

The key difference is what a "token" is, meaning the unit that attention operates on.

TabPFN v2 7.2M params, 12 blocks

Every cell is its own token (features actually go in pairs). The 12 blocks alternate the two attentions. Labels sit in a target column; the prediction is read from the query row's target cell.

TabICL v2 27.6M params

A column-embedding network first compresses each row's features into one vector. Labels are added, then a 12-block transformer mixes rows. After the squeeze, individual features no longer have their own tokens.

Mitra 75.7M params, 12 blocks

Per-cell layout like TabPFN, but every column uses the same embedding and nothing encodes column position. Column order therefore can't matter, by construction.

3. Finding 1: where class information appears inside each model

They fit a linear probe at every layer: "if I only had this layer's numbers, could a linear classifier recover the label?"

TabPFN v2: almost nothing until layer 9, then a jump

Linear-probe accuracy per TabPFN v2 layer, mean over 49 datasets (Table 12). The jump from layer 8 to layer 9 (0.47 to 0.78) is the paper's "crystallization point". Dashed lines are mine, from their Tables 82 and 1.

TabICL v2: readable almost from the start

A nearest-neighbor classifier on TabICL's representation right after the first ICL block already reaches 0.824, against 0.864 for the full model. So the 26M-parameter ICL transformer, about 95% of TabICL's parameters, adds only about 4 points. The paper calls this an inefficient design.

Mitra: rises toward layer 9

Mitra v1 probe accuracy per layer, 45 datasets (Table 36). Note: they probe a different token here (feature cells averaged) than for TabPFN.

One critical early block per model

  • TabPFN block 0. Skip its MLP and the frozen probe at layer 9 loses 37.6 points. But a retrained probe still finds the class information. So block 0 doesn't hold the information, it sets the coordinate system the later layers expect.
  • TabPFN block 9. Knock it out: the frozen probe loses 32.9 points, the retrained probe loses little. Block 9 "writes" the class structure into the readable form.
  • TabICL "ColEmb-2" (the last part of the column embedder): zeroing it costs 28 points. No single ICL block costs more than 3.
  • Mitra block 0: replacing it with identity costs 15.8 points (v1) and 41.1 points (v1.1).

Geometry: TabPFN squeezes its representation hard early (effective rank about 40 at blocks 0-1, about 10 at block 2), then partly re-expands. TabICL expands steadily through the stack.

My take: this probe result looks broken. On layers 0-8 the TabPFN probe scores 0.29-0.52, and eight of those nine layers sit below 0.50, which is what you'd get by always guessing the most common class (their own Table 82). A logistic regression trained and tested on the same kind of data basically can't be systematically worse than that.

My best guess at the cause: they probe the target-column token. For context rows that token holds the label, for query rows it doesn't. So the probe is trained on one kind of token and tested on another. At layer 9 the query rows pull in labels through the vote (finding 2), the two kinds start looking alike, and the probe suddenly "works". If that's right, the jump is the vote measured a second time, not independent evidence that class structure forms late.

Supporting signs: their input-layer representation has effective rank 0.00 (Table 15), meaning the token they read at the input is constant. Mitra's probe (a different token) rises gradually with no jump, yet the text calls it "a similar late-jump profile". And the main text and appendix describe the probe's test rows differently (query rows vs held-out context rows).

Update: Balef et al. (ICML 2026) probe the same TabPFN v2 checkpoint using query rows only, precisely to avoid label leakage, and with per-layer retrained heads they find the answer readable by about layer 5. See that explainer.
How sure: strong evidence that something is off; the exact cause is my guess.

4. Finding 2: how each model turns its insides into a prediction

This is the heart of the paper. For each model they propose a simple rule and test it.

4.1 TabPFN v2: an attention-weighted vote at layer 9

The rule. At layer 9, read off how much attention the query row pays to each context row. Each context row "votes" for its own label with that weight:
P(class c) = average over heads of Σi attentioni · [labeli = c]

  • Layer 9 is special. It has the sharpest attention of all layers on 49 of 49 datasets. On average the single most-attended context row gets 0.93 of the weight, so the query mostly looks at a handful of rows.
  • The vote matches the model. Correlation with the model's probabilities is r = 0.89 on average: 0.93 on binary problems, 0.80 on ten-class problems.
  • Causal test. Force layer 9 attention to be uniform and accuracy drops from 0.874 to 0.488, which equals always guessing the majority class.
  • The vote is spread over all 6 attention heads. Zeroing any single head costs at most about 4 points on average.

Share of the query's attention that goes to context rows of the same class as the query vs other classes, mean over datasets (Figure 1b). At layer 8 attention ignores class; at layer 9 it concentrates on same-class rows.

4.2 The similarity is learned, not raw distance

Which rows does layer 9 attend to? Not simply the ones closest in the raw input. They regressed the attention weights on several distance measures (Table 80):

How much of the layer 9 attention pattern each predictor explains (mean R², 49 datasets).

And plain k-nearest-neighbors agrees with TabPFN on about 78-81% of test points in input space, but only 54-56% when run on TabPFN's own layer 9 representation (Table 19). So TabPFN is not a kNN, neither in input space nor in its own final space. It builds its own notion of "similar rows" by layer 8, then votes. The paper calls this a learned similarity.

4.3 TabICL v2: nearest class prototype at the last layer

The rule. At the final layer, average the representations of all context rows of each class to get one "prototype" per class. Predict the class whose prototype is nearest to the query.

  • The prototype rule reaches 0.854 vs the model's 0.864. kNN on the final layer agrees with TabICL on about 94% of points.
  • TabICL's attention does not track distance (correlation below 0.08 at every block) and never gets sharp. Forcing uniform attention in any one block barely matters; forcing it in all 12 costs 29 points. The work is spread out.

4.4 Mitra: a vote, like TabPFN

The layer 9 vote reaches 0.815 vs Mitra's 0.860, a 4.5-point gap, so it doesn't fully pass their bar. It still beats every other simple rule, so they put Mitra in the "vote over context rows" family with TabPFN.

Reading it: TabICL's final layer is so neatly organized by class that almost any simple rule works on it (prototype, kNN, linear). TabPFN's final layer is not: even a freshly fitted linear head gets only 0.617. TabPFN's answer lives in the attention pattern at layer 9, not in a class-clustered final representation.

4.7 What counts as "faithful"

A rule is called a faithful surrogate when all four hold: (i) its probabilities correlate with the model's at r ≥ 0.85, (ii) its accuracy is within 3 points, (iii) its predicted labels agree with the model's (Cohen's κ ≥ 0.8), and (iv) it survives an intervention that keeps only the parts the rule names. The vote passes on 40/49 datasets for TabPFN; the prototype passes on 43/49 for TabICL.

My take: "confirmed by causal intervention" is too strong. Forcing uniform attention at layer 9 shows that layer 9 attention is necessary. It doesn't show that a vote is what happens: breaking any important component would also break the model. The authors know this. In the appendix they call layer 9 attention "necessary but not sufficient", show that MLP knockouts also collapse accuracy (Table 44), and write that the rules "are not claims about internal computation". The abstract doesn't say that. Also, the vote is a good match on labels but a poor one on confidence: calibration error goes from 0.043 for the model to 0.201 for the vote (Table 85).
How sure: high. All of this is in their own text and tables.

5. Finding 3: order of rows, columns and classes

A table is a set of rows and a set of columns, and class names are arbitrary. So shuffling the rows, shuffling the columns, or renaming the classes should not change any prediction. That property is called permutation invariance.

  • Rows: all three models are row-order-blind by construction.
  • Columns: TabPFN and TabICL are not. Random column shuffles move accuracy by a median of 2.7 points for TabPFN (1.5 for TabICL v2) and up to 8 points on the worst dataset (Table 60). The paper notes this is one reason the released models use ensembling: averaging over several shuffled column orders.
  • Classes: no model is class-order-blind, because labels get embeddings tied to the class index.

Retraining from scratch. They pretrained TabICL v1 four times, with RoPE on/off and with a normal vs a class-order-blind output head (Table 2). Each change alone costs under 1 point; both together cost 2.6 points (0.829 to 0.803). My take, for your thesis. When TabPFN ensembles over column shuffles, each ensemble member is a slightly different function, and the final output is their average. Feature-effect plots of "TabPFN" are therefore plots of an average of models. This may also matter for McCarter's parity result, where one model failed and four succeeded (section 9).

6. Finding 4: "representation collapse" and the toy models

The worry (from the TabICL paper). If a model is completely blind to column order, two rows that are column-shuffles of each other, like 100 and 001, look identical to it. If their labels differ, it must get one of them wrong.

The cleanest idea in the paper: rows grouped by shuffling

Take 3 binary features. Group the 8 possible rows by "can I turn one into the other by shuffling columns?". That's the same as grouping by how many 1s the row has. An order-blind model must give every row in a group the same answer.

The surprise: Mitra has none of the escape routes and still doesn't collapse. Their guess is that it puts labels in early, as a slot every layer can see, and never compresses a row into one vector. Their recipe for the next model: (i) column-order-blind by construction, (ii) labels visible from the first layer, (iii) read the answer from the context labels (for example One-vs-All) rather than from a fixed class head.

My take: this is the most useful section for parity. McCarter's parity uses all D bits, so it's in the "multiset-decidable" class like majority: an order-blind model could solve it just by counting the 1s. Sparse XOR (two bits out of D) is task B, and needs pair tokens. These give two very different predictions for TabPFN. See section 9.

If TabPFN votes over similar rows and TabICL compares to class averages, some data changes should hurt them more than a model trained from scratch on the same changed data. The eight attacks, all applied to the context table:

The paper's reading. Hub poison and rank warp hurt the foundation models more than the MLP, so they hit the readouts specifically. Noise, centroid, boundary and SVD hurt the MLP at least as much, so they're generic. Cube and soft-exp hurt the MLP about twice as much, so the foundation models' pretraining already covers smooth warps.

The three attacks that decide the argument, from the table above.

My take: the attacks don't isolate the readouts.
  • Hub poison hurts XGBoost more than TabPFN (-4.8 vs -3.9). Against the MLP the gap is about 1 point, and the confidence intervals overlap (TabPFN [-5.7, -2.2], MLP [-4.0, -1.6]).
  • Rank warp is not doing what it says. A tree model doesn't care about any order-preserving change to a feature: XGBoost loses exactly 0.0 under cube warp. Yet it loses 7.6 points under "rank warp", and 13.6 on their mixed-type slice (Table 96, LightGBM 10.7). So rank warp must be changing the order somehow. My best guess: ties are broken by row index (Table 7), which turns repeated values, like categories or integers, into arbitrary distinct numbers. The mixed-type datasets, full of ties, are hit hardest: TabPFN loses 17.2 points there, TabICL 21.0 (Table 68).
How sure: the hub numbers are from their tables. The tie-breaking explanation is my best guess for why trees lose under a supposedly order-preserving change.

8. My critique, all in one place

What's good. 49 classification and 10 regression datasets, 5-20 seeds, bootstrap confidence intervals, multiple-testing corrections, real interventions (forcing, knockouts, patching), a falsifiable criterion for "faithful", a clean small theorem, and an honest claims-and-caveats table (Table 90). It's far more rigorous than most interpretability papers on these models.

9. How it connects to McCarter, parity and your thesis

Everything in this section is my own analysis.

Why parity is a puzzle for a vote

Parity: D binary features, label = 1 if the number of 1s is odd. Flip any one bit and the label flips, so the most similar rows in input space always have the wrong label. A vote over input-space neighbors would be confidently wrong, and that's exactly what XGBoost does in McCarter's leave-one-out panel (about 100% error). Yet ensembled TabPFN v2 gets parity nearly right.

Bilos gives the way out: the vote runs on a learned similarity (4.2). So by layer 8, TabPFN must make rows with the same parity look similar. And section 6 suggests how: full parity depends only on how many 1s a row has. "Count the 1s, then vote among rows with the same count" solves it.

A numerical clue

If TabPFN counts and then votes, which rows fail under leave-one-out? Exactly the two rows that have no other row with the same count: all-zeros and all-ones. That predicts an error rate of exactly 2/2D:

From D = 5 to 10 it's almost exactly two wrong rows per table. That's a clue, not proof. D = 3 and 4 don't fit, and other mechanisms could also fail on exactly the two most extreme rows. The test is cheap: run it and check which two rows are wrong.

The sharper experiment: sparse XOR

Label = xi XOR xj, with the other columns as pure noise. Counting no longer helps (that's task B from section 6), and the single-feature PD/ALE plots are flat. Bilos's toy models say you need pair tokens, and TabPFN v2 processes features in fixed pairs. If those pairs are formed from neighboring columns, (0,1), (2,3) and so on (their W = 0 result suggests fixed positional pairs), then a single TabPFN model with a fixed column order should learn XOR of columns 0 and 1 more easily than XOR of columns 0 and 2.

That would be the same function with flat single-feature effects, where learnability depends on column order. It's a sharp result for a thesis about feature effects, and the prediction may well fail, which would also be informative.

What feature-effect methods would show

  • Full parity, D ≥ 3: partial-dependence and ALE plots of every single feature and every pair are perfectly flat. Only the full D-way interaction carries the signal.
  • Sparse XOR: single-feature plots are flat, but the 2D plot of the right pair shows the XOR pattern clearly.

Experiments this suggests (not run yet)

  1. McCarter's parity, D = 5-7, leave-one-out, 1 vs 4 ensemble members, with the v2 checkpoint loaded explicitly. Print which rows are wrong.
  2. Sparse XOR in the same pair vs in different pairs, with 1 ensemble member so the column order stays fixed.
  3. Read out the layer 8 representation on parity: do rows with the same count of 1s sit close together?

11. How to read the actual paper
  1. Start with Figure 1 (page 2). Panels (a)-(c) are the two readouts; (d) is the transplant; (e) the attacks; (f) the invariance fix.
  2. Read section 3 closely (pages 4-5), with section 4 of this page open next to it.
  3. Read section 5.1 (pages 7-8) together with the 8-row table in section 6 of this page.
  4. Skim sections 2, 4, 6. Their main results are in the summaries here.
  5. Appendix tables worth opening: 12 (probe per layer), 17 (vote per dataset), 19 and 80 (learned similarity), 21 (toy models), 73 (transplant), 60 (column-shuffle spread), 65 and 96 (attacks), 85 (calibration), 90 (their own claims-and-caveats summary).

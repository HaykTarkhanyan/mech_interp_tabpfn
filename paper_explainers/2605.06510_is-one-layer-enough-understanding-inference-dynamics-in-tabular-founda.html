1. The paper in one minute

The question. Bilos asked what TabPFN computes. This paper asks when: as a test row passes through the layers, at which depth does the answer form, and are all those layers needed? They borrow six standard tools from LLM interpretability and run them on six tabular foundation models.

The answers.

  1. The answer is there early, just not in a readable form. If you train a fresh decoder for each layer, most models already predict well after a few layers. For TabPFN v2 that's layer 5 of 12. The model's own output head only works near the end, so the late layers mostly translate the answer into the form that head can read.
  2. The first layer is special. Skip it and performance collapses for good. Skip almost any middle or late layer and performance dips, then the following layers repair it ("self-repair").
  3. Depth works like repeated refinement. Layers come in blocks with similar representations, and each layer adds a bit on top of the previous ones. The paper calls this "iterative inference".
  4. One layer looped six times is about as good as six layers. In a small TabPFN clone, a single layer run six times matches the 6-layer model using only 20% of the parameters. A single layer run once is clearly worse.
My take, one line. A solid, honest, broad "where in depth" study. Its most useful result for you is that TabPFN v2's late "jump" (Bilos's layer 9) is about alignment with the output head, not the arrival of information, which backs up my critique of Bilos's probe. The title oversells a bit: looping saves parameters, not compute, and was only shown at toy scale. Details in section 8.

2. Background you need first

2.1 The residual stream

In a transformer, each layer doesn't replace the representation, it adds an update to it: hnext = h + layer(h). That running sum is called the residual stream. Two consequences matter here. You can stop after any layer and look at h. And if a layer is removed, the stream still flows, so later layers may fix the damage.

2.2 Two views of what depth does

Circuit viewEach component has its own specialized job (one head copies, one layer compares, ...). Removing a component removes that job.
Iterative-inference viewLayers keep nudging the same representation toward the answer, with overlapping work. Removing one is survivable because the others cover for it.

The paper says they aren't mutually exclusive, and its evidence mostly supports the second view for tabular models.

2.3 Logit lens and tuned lens (from LLM research)

The logit lens: take an intermediate layer's state and push it straight through the model's final output head, to see what the model "would answer" at that depth. It's often misleading, because intermediate states aren't in the format the final head expects. The tuned lens fixes this by learning a small adapter per layer. This paper's version, the "tabular logit lens", retrains a copy of the output head for each layer (on synthetic data, with the model frozen) and compares it with the original head.

Schematic. If the orange heads predict well at layer 3 while the blue one doesn't, the information is there but in a different "format" than the final head expects.

3. The six experiments, one by one

They go from "look at the representations" (1-4) to "break the model and watch" (5-6).

Experiment 1: embedding similarity

What: compare every layer's representation with every other layer's, using cosine similarity and CKA (a similarity measure for whole sets of representations).
Found: neighboring layers are similar, and the bigger models (TabPFN v2, 2.5, LimiX) form visible blocks of layers that barely change the representation, with bigger jumps between blocks. TabPFN v1 and TabICL show no clear blocks.

Takeaway 1. TFMs often form blocks in which the embeddings remain similar.

Experiment 2: separation gap

What: at each layer, how much farther apart are rows of different classes than rows of the same class? A bigger gap means classes are easier to tell apart. They track it separately for context ("support") and query rows, and for feature tokens vs label tokens.
Found: the gap grows with depth, noisily. Context rows' label tokens start high, of course, since they contain the label. Feature tokens separate first, the query's label token later. TabPFN v2 shows a jump around layer 5.

Takeaway 2. TFMs incrementally increase the distance between samples from different classes.

Experiment 3: probing classifiers

What: train a logistic regression on one layer's query-row representations and test it on the same layer or other layers.

An important design choice: they probe only query rows, and train the probe on extra query rows (half of the training set moved over), because "support embeddings inherently contain label information". This is exactly the trap I suspected in Bilos's probe (see section 7).

Schematic of their Figure 5. A probe trained at an early layer keeps working on later layers, but not the reverse. So later layers keep the old information and add new information on top.

Takeaway 3. Each layer cumulatively enriches the representation by adding new features while preserving previous ones.

Experiment 4: the tabular logit lens

The most important experiment; it has its own section 4.

Takeaway 4. Representations are already formed for a reliable prediction in the early layers, but not necessarily aligned with the original decoder.

Experiment 5: layer ablation (skip, repeat, swap)

Schematic. Skip = leave one layer out. Repeat = run one layer twice. Swap = run two neighboring layers in the wrong order.

  • Skip: skipping an early layer hurts the most; skipping middle or late layers costs little or nothing. TabICL and LimiX-2M survive even early skips, because their strong input encoders already did that work.
  • Repeat: repeating some layers even helps slightly (LimiX-16M, TabPFN v1), as you'd expect if layers do refinement.
  • Swap: models are generally sensitive to swapping, TabPFN v2 most of all, and more so than LLMs.
Takeaway 5. Early layers contribute the most, while later layers perform iterative refinement of the representation.

Experiment 6: self-repair

What: skip one layer, then use the per-layer decoders to watch performance at every following layer. If it drops right after the skip and recovers later, the later layers "repaired" the damage.
Found: skipping the first layer is never repaired. Skipping middle or late layers usually is, especially in TabPFN v2.

Takeaway 6. Self-repair generally occurs after layer ablations, except for the first layer.

4. The key plot: the "tabular logit lens"

For each layer: how well does the model's original output head predict from that layer, vs a head retrained for that layer? Pick a model:

Mean "normalized ROC-AUC" across datasets, approx., read off Figure 6. The dashed line is the full model.

How to read it:

  • TabPFN v1: the two lines lie on top of each other and reach the top by layer 2-3. Information arrives early, and it arrives in the final format.
  • TabPFN v2: the retrained head is near the top by layer 5. The original head even gets worse around layers 5-6 and only catches up at layers 8-10. For about four layers the answer is present, but the original head can't read it.
  • TabPFN 2.5 (24 layers): same pattern, stretched out. The retrained head jumps at layer 5, the original head trails until roughly layer 12-20.

Their plain-language summary: in TabPFN v2 and 2.5, the late layers mostly rewrite an already formed answer into the head's format. The other models show this much less.

5. The four stages of inference

Combining the experiments, they propose four stages, named after a similar 4-stage story for LLMs (Lad et al., 2025):

StageWhat happensEvidence
1. Latent mappingTurn the input encoding into a representation the rest of the stack can work with.Decoders can't read anything yet; skipping these layers is catastrophic. Weaker in models with strong encoders (TabICL, LimiX-2M).
2. Feature engineering and labelingBuild features and pull label information into the query; classes separate.Retrained heads shoot up; the separation gap grows.
3. Prediction ensemblingConvert the formed answer into the format the original head reads.Retrained heads are already saturated while the original head keeps improving. Clear only in TabPFN v2 and 2.5.
4. Prediction calibrationAdjust confidence without changing the ranking.ROC-AUC is flat, but balanced accuracy jumps and output entropy keeps changing.

The stages can overlap. Differences from LLMs: tabular models are more sensitive to swapping layers, and their last layer matters less for classification (but in regression the TabPFN family's last layer does matter, appendix E).

6. So, is one layer enough?

If middle layers largely redo similar work, maybe one layer used repeatedly can replace them. They test this with nanoTabPFN, a small open reimplementation of TabPFN v2, pretraining three versions from scratch on the TabICL prior:

ModelHow it runsParametersPretraining (A100 hours)Final performance (approx.)
nanoTabPFN, 6 layers6 different layers3.72M62.30.945
nanoTabPFN, looped1 layer, run 6 times0.75M (20%)68.80.945
nanoTabPFN, 1 layer1 layer, run once0.75M11.90.82

Mean normalized performance on PMLBmini + TabArena, approx., read off Figure 9 (TabPFN 2.5 is the 1.00 reference line in that figure). Parameters and hours are from Tables A.7, A.8 and A.10.

Their answer: one layer used once is not enough (0.82). One layer used six times matches six separate layers. So depth is mostly repeated refinement, not six different transformations. Their caveats: small scale only, and still clearly behind TabPFN 2.5.

My take: read the title as "one layer's worth of parameters".
  • The looped model does the same amount of compute as the 6-layer one: same forward cost, and even slightly longer pretraining (68.8 vs 62.3 hours). It saves memory for weights, not time.
  • The appendix says looping "reduces the total number of parameters by 20%". Their own Tables A.7/A.8 (3.72M vs 0.75M) show it reduces them to 20%, as the abstract correctly says.
  • In their per-dataset scatter (Figure 9, right) one PMLBmini dataset collapses under looping: about 0.4 for 6 layers but about 0.05 for the looped model. They don't comment on it.
How sure: high. All from their own tables and figures.

7. How it fits with Bilos et al.

Both papers study the same TabPFN v2 checkpoint (7.24M parameters, 12 layers), so they can be compared directly.

QuestionBilos et al.Balef et al. (this paper)
When is the class readable?Linear probe near chance until layer 8, jump at layer 9.Retrained head near the top by layer 5; the original head jumps late (layers 8-10).
Is the first block critical?Yes: block 0 "sets the coordinate frame".Yes: skipping it is catastrophic and never repaired.
Can middle/late layers go?Most single-block knockouts cost little.Yes, with self-repair.
What happens late?A sharp attention vote over context rows."Prediction ensembling" (format conversion) and calibration.
What do they look at?Attention patterns, readout rules: what is computed.Layer-level dynamics: when and where.
EnsemblingNot reported.Off (1 member), stated.
My take: this paper supports my critique of Bilos's probe. In the Bilos explainer I flagged that their layer 0-8 probe scored below the majority-class baseline, and guessed that it mixed tokens that contain labels with tokens that don't. Balef avoids exactly that trap (query rows only) and, with retrained heads, finds the answer readable by layer 5. So Bilos's "late crystallization" is best read as "the moment the answer gets into the output head's format", not "the moment the information appears". Bilos's own frozen-vs-retrained probe results already hinted at this.

A combined story, my synthesis, not in either paper: layers 1 to about 5 build features and pull in label information; the following layers convert that into the format the output head reads, and in TabPFN v2 that conversion runs through the sharp layer 9 attention vote Bilos found; the last layers calibrate confidence. Two loose consistencies: Balef's retrained head jumps around layer 5, and Bilos found blocks 5-6 to be the second most damaging to knock out.
How sure: medium. The two papers count layers differently (Bilos starts at 0) and use different datasets and metrics, so don't match single layers exactly.

8. My critique

What's good. Six models, two benchmark suites, binary + multiclass + regression, a carefully designed probe that avoids label leakage, retrained per-layer heads trained on synthetic data (so they can't overfit the test datasets), clear takeaways, a public code link, and an honest limitations paragraph. Peer-reviewed at ICML.

9. What it means for parity and your thesis

Everything in this section is my own analysis.

  • Their benchmark contains Boolean puzzles. PMLBmini includes parity5 (32 rows), mux6 and corral: exactly the functions where feature effects are uninformative. The paper only reports averages, but it links a GitHub repo (I haven't checked what's in it), so you may be able to pull the per-dataset layer curves for these.
  • A sharper test of my "count, then vote" parity hypothesis. Use their query-only probe protocol and, at each layer, probe two targets: the number of 1s in the row, and the parity itself. If TabPFN counts first, the count should become linearly readable before parity does. This uses the leak-free probe design from this paper on the question raised by McCarter and Bilos.
  • A "feature-effect lens" for your thesis. With per-layer heads you can compute PD/ALE curves at every layer and watch when an effect's shape forms. If Balef's stages hold, shapes should settle around mid-depth and the last layers should mostly rescale confidence (their "calibration" stage). That's a testable claim connecting depth to feature effects. One cost check first: their heads took 13.6 A100-hours for TabPFN v2. Whether the repo ships trained heads is something I haven't verified.
  • Practical point. If you ever explain TabPFN through an intermediate layer, use a retrained head. The original head read at middle layers gives misleading, even below-chance, answers for TabPFN v2.

10. Glossary
TFMTabular foundation model (TabPFN, TabICL, LimiX, ...).
Support / querySupport = the labeled training rows given in context. Query = the rows to predict.
Residual streamThe running representation that every layer adds its update to.
Decoder / output headThe small network at the end that turns the final representation into class probabilities.
Logit lensReading an intermediate layer with the model's own final head.
Tuned lens / "tabular logit lens"Reading each layer with a head trained for that layer.
Individual decoderThe per-layer retrained head (orange in the charts).
Cosine similarity, CKATwo ways to measure how similar two layers' representations are. CKA compares whole sets of vectors.
Separation gapAverage distance between different-class rows minus that between same-class rows.
ProbeA simple classifier (here logistic regression) trained on a layer's representation.
AblationRemoving or altering a component (skip, repeat, swap a layer) to see what changes.
Self-repairLater layers making up for a removed earlier layer.
Iterative inferenceThe view that layers gradually refine one shared representation.
Looped transformerRunning the same layer several times instead of stacking different layers.
ROC-AUCProbability that a random positive gets a higher score than a random negative. 0.5 = chance, 1.0 = perfect. Ignores calibration.
Balanced accuracyAccuracy averaged over classes. Depends on the decision threshold, so it reacts to calibration.
Entropy (of the output)How spread out the predicted probabilities are. Low = confident.

  1. Figure 1 (page 1) is the whole paper in one picture: retrained heads succeed early, the original head late.
  2. Figure 2 (page 4) shows the experiment types; then read the six numbered experiments in section 3 (pages 4-6). Each ends with a blue "Takeaway" box, which section 3 of this page repeats.
  3. Figure 6 (page 6) is the one to study; use the chart in section 4 of this page.
  4. Section 4, "Discussion" (pages 6-7) has the stages; Table C.1 in the appendix spells them out.
  5. Section 5 (pages 7-8) is the looped model; check Tables A.7, A.8 and A.10 for parameters and training time.
  6. Skip on a first read: the parameter tables A.1-A.6, the dataset lists, and the many per-benchmark repeats in appendices B, D and E.
